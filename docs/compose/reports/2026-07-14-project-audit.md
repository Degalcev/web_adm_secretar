# Аудит проекта web_adm_secretar — Замечания и рекомендации

## 1. Сессии и аутентификация

### Текущее состояние
- TTL сессии: **24 часа** (`expires_hours=24`)
- Очистка: при старте сервера + каждые 6 часов (`periodic_session_cleanup`)
- Rate limiter: 5 попыток/минуту на вход

### Проблемы

**1.1. Нет обновления TTL при активности пользователя.**
Сессия истекает через 24ч с момента создания, даже если пользователь активно работает. Если он открыл панель утром и работает весь день — вечером сессия умрёт.

> **Рекомендация**: Обновлять `expires_at` при каждом запросе (в auth middleware). Простой UPDATE раз в N минут или при каждом запросе. Это стандартный подход для "rolling session".

**1.2. Нет "Запомнить меня".**
При закрытии браузера пользователь теряет сессию (cookie httponly, не session cookie — но TTL 24ч). Реально: cookie живёт пока браузер открыт + 24ч. Но нет опции "оставаться залогиненным дольше" (например, 30 дней).

> **Рекомендация**: Добавить checkbox "Запомнить меня" на форме логина. При отметке: TTL сессии = 30 дней, cookie max-age = 30 дней. Без отметки: текущее поведение (24ч / browser session).

**1.3. Нет принудительного выхода при смене пароля.**
Если админ сменил пароль пользователю, старые сессии остаются активными.

> **Рекомендация**: При смене пароля удалять все сессии пользователя (`DELETE FROM sessions WHERE user_id = ?`).

**1.4. CSRF token не ротируется.**
CSRF token генерируется один раз при логине и живёт всю сессию.

> **Рекомендация**: Минимально — acceptable для admin panel. Максимально — ротировать при смене пароля.

## 2. Предзагрузка данных (Preloading)

### Текущее состояние
- `preloadAllData()` вызывается из `initDashboard()` и `initCalendar()`
- `_preloaded` флаг предотвращает повторную загрузку
- `restoreFromCache()` читает `localStorage.dash_cache` при старте (НО **не вызывается** — `initPreloader()` нигде не вызывается!)
- SSE обновляет данные в реальном времени

### Проблемы

**2.1. `initPreloader()` определён, но не вызывается.**
Функция `initPreloader()` в `preloader.js` существует, но `app.js` её не вызывает. Это значит:
- `restoreFromCache()` никогда не выполняется при старте
- Данные загружаются ТОЛЬКО при переходе на dashboard или calendar
- При прямом заходе на `/conferences/` данные загружаются через `loadAllEvents()`, но `store.allLocations` и `store.allOrganizers` могут быть пустыми (их загружает `ensureOrgsAndLocs()`)

> **Рекомендация**: Вызывать `initPreloader()` в `app.js` перед `checkAuth()`. Это даст мгновенные данные из кэша при повторном входе.

**2.2. Preload не обновляется при изменениях.**
`_preloaded = true` блокирует повторный вызов. Если событие создали на VKS странице — календарь не увидит его до перезагрузки (SSE обновляет `store.allEvents`, но `_preloaded` не сбрасывается).

> **Рекомендация**: Убрать `_preloaded` флаг. Или сбрасывать его при получении SSE-событий. Или вызывать `preloadAllData()` при каждом переходе на dashboard/calendar (она быстрая — 1 запрос).

**2.3. Нет fallback при ошибке preload.**
Если `/admin/api/preload` вернул 500 — `store.allEvents` остаётся пустым, календарь пустой.

> **Рекомендация**: Уже частично исправлено (fallback на `loadAllEvents()`). Дополнительно: добавить retry с exponential backoff.

## 3. Выход пользователя (Logout)

### Текущее состояние
- `POST /admin/logout` — удаление сессии на сервере
- Очистка store (`allEvents = []`, etc.)
- `showLogin()`, `history.replaceState('/', '')`

### Проблемы

**3.1. SSE не закрывается при logout.**
`_eventSource` остаётся активным, продолжает слушать и обновлять пустой store. При повторном входе — дублирование обработчиков.

> **Рекомендация**: Добавить `_eventSource.close()` в `logout()`.

**3.2. `calStopNowLineTimer()` не вызывается.**
Таймер now-line продолжает работать после logout, пытаясь обновить DOM который скрыт.

> **Рекомендация**: Вызывать `calStopNowLineTimer()` в `logout()`.

**3.3. `_preloaded` не сбрасывается.**
При повторном входе `preloadAllData()` вернёт данные из памяти (уже очищенного store), а не загрузит свежие.

> **Рекомендация**: Сбрасывать `_preloaded = false` в `logout()`.

**3.4. localStorage не очищается.**
`dash_cache` и `vks-theme` сохраняются между сессиями. Это OK для темы, но `dash_cache` может содержать устаревшие данные.

> **Рекомендация**: Очищать `dash_cache` при logout. Тему оставлять.

**3.5. Нет обработки 401 в logout.**
Если сессия уже истекла, `POST /admin/logout` вернёт 401 (middleware блокирует). Но logout всё равно очищает клиентское состояние.

> **Рекомендация**: OK — клиентское состояние всё равно нужно очищать. Но можно показать toast "Сессия истекла" вместо молчаливого выхода.

## 4. SSE (Server-Sent Events)

### Текущее состояние
- Подключение сразу при загрузке страницы (`initSSE()` в `app.js`)
- Auto-reconnect с задержкой 5 секунд
- Обновления: events, locations, organizers, users

### Проблемы

**4.1. SSE подключается ДО проверки авторизации.**
`initSSE()` вызывается в `app.js` до `checkAuth()`. Если пользователь не авторизован — SSE endpoint вернёт 401, reconnect будет бесконечно повторяться.

> **Рекомендация**: Подключать SSE только после успешного `checkAuth()`. Или проверять авторизацию в SSE handler.

**4.2. SSE не учитывает текущую страницу.**
При SSE-обновлении events — обновляется `store.allEvents` и вызывается `renderCalendar(false)` или `renderVksBoard()` в зависимости от текущей страницы. Но если страница не активна — обновление всё равно происходит.

> **Рекомендация**: Minor issue. Можно оптимизировать: обновлять store всегда, но рендерить ТОЛЬКО если страница активна. Уже частично сделано (проверка `currentPage`).

**4.3. Нет debounce на locations/organizers/users.**
Events имеют debounce 300ms, но locations/organizers/users обновляются без задержки. При массовых изменениях — множественные ререндеры.

> **Рекомендация**: Добавить debounce 300ms на все SSE-каналы.

## 5. Frontend — общие замечания

**5.1. Нет индикации загрузки.**
При первом входе пользователь видит пустую страницу пока данные загружаются. Нет skeleton/spinner.

> **Рекомендация**: Добавить skeleton loader на dashboard и calendar.

**5.2. Нет offline-обработки.**
Если интернет пропал — fetch-запросы падают молча. Пользователь не знает что данные устарели.

> **Рекомендация**: Добавить toast при сетевых ошибках. Минимально — показывать "Нет соединения" при失敗е fetch.

**5.3. CSS кэширование.**
`?v=__VERSION__` — работает. Но браузер может кэшировать JS/CSS при ошибке деплоя (502). Nginx anti-cache решает это для `/admin/api/`, но не для `/static/`.

> **Рекомендация**: OK — static файлы имеют `max-age=86400` с версионированием. При деплее версия меняется.

**5.4. `escape()` для XSS.**
Используется自制 `esc()` функция. Нужно убедиться что она экранирует все HTML-сущности.

> **Рекомендация**: Проверить `esc()` — если это `textContent = ...` approach, это безопасно. Если innerHTML — нужна полная экранировка.

## 6. Backend — общие замечания

**6.1. Нет rate limiting на API кроме login.**
Любой authenticated user может долбить API без ограничений.

> **Рекомендация**: Добавить общий rate limit (например, 100 запросов/минуту на пользователя).

**6.2. Нет request logging.**
Нет логов входов/выходов, failed login attempts (кроме rate limiter).

> **Рекомендация**: Логировать: successful login, failed login (с IP), logout, password change.

**6.3. `organizers.py` — дублированная функция.**
`update_organizer_handler` определена дважды — pre-existing bug.

> **Рекомендация**: Удалить дубликат.

## 8. Ответы на вопросы пользователя

### Когда загружать данные?
**При входе (checkAuth → showMain):**
- Вызвать `initPreloader()` — восстановить из кэша + запустить фоновую загрузку
- SSE подключать ТОЛЬКО после успешного checkAuth

**При навигации:**
- Dashboard: `preloadAllData()` (если `_preloaded = false`)
- Calendar: `preloadAllData()` с fallback на `loadAllEvents()`
- VKS: `loadAllEvents()` (уже есть)

**При выходе:**
- Закрыть SSE (`_eventSource.close()`)
- Остановить now-line таймер
- Очистить store
- Сбросить `_preloaded`
- Очистить `dash_cache` из localStorage
- НЕ очищать `vks-theme` (персональная настройка)

### Ограничена ли сессия?
Да — **24 часа** фиксированно. Нет обновления при активности. Нет опции "запомнить меня".

**Нужно ли это?** Да. 24ч — разумный TTL для admin panel. Но rolling session (обновление при активности) повышает UX без потери безопасности.

### Сбрасывать ли все данные при выходе?
**Да.** `store.allEvents`, `allLocations`, `allOrganizers`, `allUsers` — всё очищать. Это предотвращает утечку данных между пользователями на одном устройстве.

**Кроме:** `localStorage.vks-theme` — персональная настройка, не привязана к сессии.

### "Запомнить меня"?
**Да, стоит добавить.** Реализация:
- Checkbox на форме логина
- При отметке: `expires_hours=720` (30 дней) вместо 24
- Cookie `max-age=2592000` (30 дней)
- Без отметки: текущее поведение
