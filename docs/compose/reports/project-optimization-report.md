## 1. Новая функциональность

### 1.1 Расширенная система мероприятий
**Статус**: Реализована (базовая функциональность)

**Что implemented:**
- 5 типов мероприятий: ВКС, Совещание, Встреча, Заседание, Приём
- Система участников (связь many-to-many через `event_participants`)
- Серии повторяющихся мероприятий (`event_series` + `event_series_exceptions`)
- Курсорная пагинация для large datasets
- Отдельная страница мероприятий с VKS-стилем карточек

**Технические детали:**
- Бэкенд: 4 новых миграции, 3 новых модели SQLAlchemy
- API: `GET /admin/api/events` с фильтрами и пагинацией
- Фронтенд: Модалка мероприятий (`event-modal.html`), страницы `/events/` и `/events/completed/`

**Проблемы:**
- Функция повторения (repeat) **не интегрирована** — UI собран, бэкенд готов, но bridge отсутствует
- Статистика не учитывает режим "Завершённые мероприятия"

### 1.2 Реформирование авторизации
**Статус**: Завершено (v1.0.160)

**Улучшения:**
- Единый `auth_middleware` заменил декораторы `@admin_required`/`@auth_required`
- Rolling session (TTL обновляется при каждом запросе)
- "Запомнить меня" (30 дней vs 24 часа)
- Login по логину ИЛИ MAX ID
- CSRF multipart для FormData (совместимость с загрузкой файлов)

**Безопасность:**
- Cookie domain из конфигурации
- Nginx anti-cache headers
- Cleanup expired sessions при старте + каждые 6 часов

### 1.3 Календарь VKS
**Статус**: Оптимизирован

**Улучшения:**
- SVG feDropShadow вместо CSS filter (решение проблемы overflow:hidden)
- Мобильный вид: компактные вкладки, фильтр залов, свайп
- Кнопка "+ Добавить" в тулбаре
- Hover через JS position:fixed (обход overflow цепочки)

### 1.4 Модалка VKS — Compact Flat дизайн
**Статус**: Завершено

**Особенности:**
- Accent bar (4px градиент) по статусу
- Drawer overlay для таймлайна аудита
- Блокировка при редактировании (lock/unlock)
- Документы с scroll и gradient fade

## 2. Оптимизации производительности

### 2.1 Бэкенд
- **Preload API**: Один запрос `/api/preload` вместо трёх
- **Batch загрузка документов**: `WHERE event_id = ANY($1)` вместо N+1
- **Cursor-based пагинация**: Реализована в `app/routes/vks.py` (курсор `(date, time)`)
- **Session validation через JOIN**: 1 запрос вместо 2 в middleware

### 2.2 Фронтенд
- **Store централизация**: Единый объект `store` вместо рассинхронизированных переменных
- **SSE оптимизация**: Обновление только активных страниц
- **Partial loading**: Модалки загружаются async через Promise
- **LocalStorage кэш**: `restoreFromCache()` для мгновенной загрузки

### 2.3 База данных
- **Индексация**: Таблицы `events`, `sessions`, `event_history`
- **Каскадное удаление**: FK CASCADE для документов и истории
- **Нормализация типов**: 12 типов → 5 типов через UPDATE

## 3. Проблемы безопасности

### 3.1 КРИТИЧЕСКАЯ: XSS в print.js (ОТЛОЖЕНО)
**Файл**: `app/static/js/print.js:40-49`

```javascript
rows += `<td>${e.type || 'ВКС'}</td>`;
rows += `<td>${e.description || ''}</td>`;
rows += `<td>${participants}</td>`;
```

**Проблема**: Значения вставляются raw в HTML. Если описание содержит `<script>` или event handlers — выполнится в браузере каждого администратора при нажатии "Печать".

**Вектор атаки**: Любой пользователь, создающий мероприятие с вредоносным описанием, может выполнить JS в браузере других администраторов.

**Решение**: Пользователь решил **отложить** исправление, так как планирует переделать печать на PDF. PDF генерация безопасна по умолчанию (нет HTML-инъекций).

### 3.2 ВАЖНАЯ: Утечка внутренних ошибок
**Файл**: `app/routes/vks.py:199-201`

```python
return web.json_response({'ok': False, 'error': str(e)}, status=500)
```

**Проблема**: `str(e)` может содержать внутренние сообщения ошибок (пути, SQL-запросы).

**Исправление**: Возвращать generic "Ошибка сервера", логировать полное исключение.

## 4. Архитектурные проблемы

### 4.1 Дублирование кода (ИСПРАВЛЕНО)
**Файл**: `app/static/js/events.js:22-25` и `90-98`

Двойное определение `eventsFilterQuick` — первая версия (неполная) перезаписывается второй (полной). Мёртвый код создаёт путаницу.

**Исправлено**: Удалена первая версия `eventsFilterQuick` (строки 22-25), оставлена полная версия (строки 90-98).

### 4.2 Непоследовательная статистика
**Файл**: `app/static/js/events.js:27-28`

```javascript
const active = (store?.allEvents || []).filter(e => !e.completed && e.type !== 'ВКС');
```

На странице "Завершённые мероприятия" статистика показывает только активные события. Нужно учитывать режим отображения.

### 4.3 Магические числа
`limit=10000` захардкожен в 4 файлах. Должен быть общей константой.

### 4.4 Мёртвый CSS
`.events-tabs` и `.events-tab` стили определены, но не используются (используется `<select>`).

### 4.5 Несоответствие в календаре: цвета залов vs типов (ИСПРАВЛЕНО)
**Файл**: `app/static/js/calendar.js:322` и `app/static/css/calendar.css:321-368`

**Проблема**: 
- В `calendar.js` события рендерятся с классами `cal-ev h${hIdx}` (цвет зала)
- В `calendar.css` определены ОБА набора классов: `.cal-ev.h0-h3` (цвета залов) И `.cal-ev.type-vks` (цвета типов)
- В плане `2026-07-14-extended-events.md` (Task 6.1) написано что события должны иметь цвета типов
- В `CLAUDE.md:391` написано "цвет по hall (h0-h3)"

**Текущее состояние**: JavaScript применяет цвета залов, хотя план предусматривал цвета типов.

**Решение**: Пользователь выбрал "Цвета по типам (как в плане)". Требуется изменить `calendar.js` для использования классов типа вместо зала.

**Исправлено**: Добавлена функция `_calGetTypeClass()` в `calendar.js`, события теперь используют классы типа (`type-vks`, `type-meeting`, etc.) вместо зала (`h0-h3`).

### 4.6 Неполное обновление при смене дня (ИСПРАВЛЕНО)
**Файл**: `app/static/js/app.js:63-69`

**Проблема**: 
- `_checkDayChange()` проверяет смену дня каждые 60 секунд
- При смене дня вызывает ТОЛЬКО `loadVksActive()` (обновление VKS доски)
- НЕ обновляет:
  - Календарь (не выбирает новый текущий день)
  - Дашборд (не пересчитывает статистику "Сегодня/Завтра/Пропущенные")
  - Страницу мероприятий (если открыта)

**Текущее состояние**: При наступлении нового дня пользователь видит устаревшие данные на календаре и дашборде.

**Исправлено**: Расширен `_checkDayChange()` для обновления всех активных страниц: VKS active, дашборд, мероприятия, календарь.
