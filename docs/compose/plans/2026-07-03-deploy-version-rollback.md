# Исправление: Откат версии при неудачном деплое

## Проблема
Если деплой падает после шага 4.5 (version.json записан), но до шага 6 (restart), версия увеличивается, а сервис не перезапускается. Следующий деплой пропустит «дыру» в версиях.

## Решение
Сохранять старую версию ДО инкремента. При ошибке на любом шаге после 4.5 — откатить VERSION обратно.

## Инкремент версии

Формат: `MAJOR.MINOR.PATCH` (например `1.0.0`)

- **MAJOR** (1) — ручное изменение, крупные архитектурные переделки
- **MINOR** (0) — ручное изменение, новые фичи
- **PATCH** (0) — **автоинкремент при каждом деплое**

Скрипт всегда инкрементирует только PATCH: `1.0.0` → `1.0.1` → `1.0.2` ...

## Задачи

### Task 1: Откат версии при ошибке деплоя

`deploy/deploy.py` — шаг 4.5:

1. Сохранить `old_ver` ДО инкремента
2. Обернуть шаги 5-6 в try/except
3. При ошибке — восстановить `VERSION` файл на VPS через `echo {old_ver} > {ver_file}`
