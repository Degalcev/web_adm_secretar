# План: Улучшение SSE — обновление данных по типу изменения

## Задача
1. Убрать фильтр `web_secretar` из SSE listener — все изменения в БД рассылаются всем
2. При SSE-событии обновлять ТОЛЬКО те данные, которые были изменены (не все)
3. Кэш localStorage обновлять при любом изменении

## Что делаем

### 1. Убираем фильтр (`app/sse_listener.py`)
- Убрать проверку `username == 'web_secretar'`
- Все pg_notify проходят без фильтрации

### 2. Обновление по типу изменения (`app/static/js/sse.js`)
При SSE-событии с `table_name`:
- `events` → обновить `_dashEvents`, `allEvents`, localStorage
- `locations` → обновить `_dashLocations`, `window.allLocations`, localStorage
- `organizers` → обновить `_dashOrganizers`, `window.allOrganizers`, localStorage
- `users` → обновить данные пользователей
- Для дашборда — перерисовать если активен

### 3. Интеграция с страницами
- При переключении на VKS — данные уже актуальны из кэша
- При переключении на пользователей/локации/организаторов — данные из кэша

## Файлы
- `app/sse_listener.py` — убрать фильтр
- `app/static/js/sse.js` — обновление по типу таблицы

## Верификация
1. User A добавляет мероприятие → User B видит обновление на дашборде
2. User A добавляет локацию → User B видит её при переходе на страницу локаций
3. Добавление из бота → тоже работает как раньше
